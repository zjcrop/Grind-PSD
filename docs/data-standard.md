# Grind-PSD 数据与测量标准

## 1. 目标与边界

`grind-psd-sieve-v1` 的目标是建立可在普通咖啡场景中复现的五段质量筛分口径。它用于相同筛具和方法下的相对比较，不替代激光衍射、动态成像或显微图像分析，也不能与这些方法的体积/数量分布 D 值直接互换。

项目参考 [ISO 3310-1:2016](https://www.iso.org/standard/62410.html) 与 [ASTM E11-24](https://store.astm.org/e0011-24.html) 对试验筛技术要求的定义，但沿用原始工具自己的档位名称与粒径边界。标准筛的“目数—孔径”关系因体系而异，因此数据库只以明确的 μm 区间作为比较边界。

## 2. 五段固定区间

| 顺序 | 原始档位标签 | 标称区间 | JSON 字段 | 记录方法 |
|---:|---|---:|---|---|
| 1 | 18 目筛上 | ≥1000 μm | `mesh18_retained_g` | 筛上质量 g |
| 2 | 24 目筛上 | 800–1000 μm | `mesh24_retained_g` | 通过上层、留在本层的质量 g |
| 3 | 35 目筛上 | 500–800 μm | `mesh35_retained_g` | 通过上层、留在本层的质量 g |
| 4 | 60 目筛上 | 300–500 μm | `mesh60_retained_g` | 通过上层、留在本层的质量 g |
| 5 | 80 目档底盘 | <300 μm | `pan80_lt300_g` | 落入底盘的质量 g |

五个原始克重是数据库的基础数据。占比由服务端重新按五档合计计算，不能只提交百分比。

## 3. 推荐操作

1. 清洁磨豆机、筛具与接粉盘，避免残粉混入。
2. 使用分辨率不低于 0.01 g 的电子秤；建议投粉 10.00 g 或 15.00 g。
3. 记录磨豆机品牌、型号、刻度和用于排序的“由细到粗数值”。
4. 研磨后尽快筛分；如使用 RDT、消静电器或其他处理，写入备注。
5. 使用固定的筛具、动作/设备、振幅和时长。默认提示为手动水平往复 60 秒，但实际方法必须如实记录。
6. 依次称量五档，不得用估算值补足总重。
7. 核对五档合计与投粉量；误差超过 10% 的记录不能进入公开库。
8. 正式比较时，每个刻度至少做 3 次独立重复，使用 `sample.replicate` 分别保存，不能先平均再只上传均值。

## 4. 质量等级

质量回收率：

```text
recovery_pct = sum(five_fraction_weights) / dose_g × 100
```

质量回收误差：

```text
mass_balance_error_pct = abs(sum(five_fraction_weights) - dose_g) / dose_g × 100
```

- A：误差 ≤2%，筛具和时长字段完整。
- B：误差 ≤5%。
- C：误差 >5% 且 ≤10%。
- D：误差 >10%，不接受公开入库。
- U：旧记录缺少投粉量或方法，未评级；只保留在本地。

质量等级只判断称量闭合与元数据完整性，不证明筛具已校准，也不替代重复性/再现性检验。

## 6. 用户库与审计

- 总库：`data/database.json`。
- 用户库：`data/users/<user_id>.json`。
- 注册 Issue 或第一次兼容性数据提交会把 `user.id` 绑定到 Issue 提交者的 GitHub 登录名。
- 用户列表检查提供前端即时反馈；工作流在串行写库时再次检查，解决同时注册同一 ID 的竞态。
- 工作流忽略前端提供的占比、指标、来源和更新时间，使用原始字段重新计算。
- 相同记录 ID、相同内容的重复提交不会重复写入；相同 ID、不同内容会被拒绝。
- 批量新增最多 20 条且必须属于同一用户 ID；任一条校验失败时整批不写入。
- 编辑不能改变记录 ID、用户 ID 或创建时间；删除必须指定记录所属用户 ID。
- 注册、编辑、删除均要求 Issue 作者与数据库中的 `githubLogin` 所有者一致。
- 每条公开记录保留 Issue 编号和 GitHub 提交者，用于审计与纠错。

## 7. 版本管理

五个区间一旦有公开数据，不允许原地修改。任何区间、单位、称量口径或方法兼容性发生破坏性变化时，必须：

1. 创建新的 `standardId`；
2. 保留旧版标准文件与旧记录；
3. 前端禁止把不同 standardId 的记录放入同一趋势线；
4. 提供显式迁移说明，而不是静默换算。
